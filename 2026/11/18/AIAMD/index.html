初读 Attention Is All You Need：从注意力机制到 Transformer

2026.11.18 6703 字 · 约 23 分钟 更新于 2026.11.18 学术

Attention Is All You Need.

然而读着读着，我发现自己快要 Lose My Attention 了。🥲

一、初读祖师爷的论文

最近突发奇想，决定拜读一下 2017 年 Google 研究团队发表的经典论文——Attention Is All You Need。

说起 Transformer，想必大家都不陌生。从自然语言处理到如今的大语言模型，Transformer 已经成为深度学习领域极具影响力的架构之一。

既然如此，总该看看这一切是从哪里开始的。

于是，我下载了论文，怀着一种朝圣般的心情，准备认真研究一下 Transformer 的诞生。

然而，理想很丰满，现实很骨感。

论文读到第二节 Background 时，我就已经有些懵了。

倒不是因为英语。事实上，文章里的大部分单词我都认识，偶尔遇到几个生词，查一下也就明白了。真正令人头疼的是：每句话似乎都能看懂，但连起来却不知道作者究竟想表达什么。

什么 Recurrent Neural Networks，什么 Convolutional Neural Networks，什么 Attention Mechanism……

这些术语看起来都很眼熟，可真要我解释它们之间的关系，一时又说不上来。

后来才意识到，问题或许不在论文，而在我自己尚未建立完整的前置知识体系。

Attention Is All You Need 毕竟是一篇面向研究人员的学术论文，而不是面向初学者的深度学习教材。作者默认读者已经了解当时主流的序列建模方法，自然不会从最基础的神经网络开始讲起。

我却试图跳过这些内容，直接理解 Transformer。

这无异于还没有学会微积分，就准备研究微分方程。

看来，还是得先补课。

二、从 FNN、CNN 到 RNN

为了理解 Transformer 为什么会被提出，首先得弄清楚它之前的神经网络究竟是什么样的。

于是，我暂时放下论文，回过头来了解几种基础架构。

1. FNN：最基本的前馈神经网络

前馈神经网络（Feedforward Neural Network，FNN）可以说是理解神经网络的重要起点。

在这种网络中，信息从输入层经过若干隐藏层，最终到达输出层，整个计算过程不存在沿时间展开的循环连接。

简单来说：

输入 → 隐藏层 → 输出

神经元通过权重、偏置和激活函数完成计算，模型则通过训练不断调整参数，使预测结果逐渐接近目标。

但是，如果输入是一句话，事情就没有这么简单了。

句子里的词语具有先后顺序，而且前后之间存在依赖关系。

传统的 FNN 本身并没有专门针对序列设计的内部状态机制。虽然可以通过特殊的输入设计处理序列，但并不天然擅长建模任意长度的上下文依赖。

2. CNN：从局部特征出发

卷积神经网络（Convolutional Neural Network，CNN）最为人熟知的应用是图像处理。

它利用卷积操作提取局部特征，再逐渐组合成更复杂的表示。

不过，CNN 并不只能处理图像，同样可以用于文本和时间序列。

在序列建模中，卷积可以同时处理不同位置，因此具有较好的并行计算能力。

但局部卷积的感受野有限。如果两个位置距离很远，信息往往需要经过多层卷积或者采用扩张卷积等方式，才能建立联系。

这就引出了另一个问题：有没有办法让两个相距很远的位置直接交互？

3. RNN：让神经网络拥有时间上的状态

循环神经网络（Recurrent Neural Network，RNN）则更适合解释序列建模的早期发展。

与普通前馈网络不同，RNN 在处理当前输入时，还会利用此前时间步的隐藏状态。

例如输入：

我 / 喜欢 / 人工智能

RNN 会依次处理这些 Token，每一步都更新自己的隐藏状态。

可以用一个简单公式表示：

ht=f(Wxxt+Whht−1+b)h_t=f(W_xx_t+W_hh_{t-1}+b)ht​=f(Wx​xt​+Wh​ht−1​+b)

其中，xtx_txt​ 是当前输入，ht−1h_{t-1}ht−1​ 是上一时间步的隐藏状态。

这样一来，网络便可以在一定程度上保留此前的信息。

LSTM、GRU 等结构则进一步改善了传统 RNN 在长距离依赖和梯度传播方面的问题。

不过，RNN 也有一个明显的限制：由于当前隐藏状态依赖上一时间步，因此很难在序列维度上完全并行计算。

而这，正是理解 Transformer 设计动机的重要线索之一。

读到这里，我才逐渐明白论文第二节 Background 的意义。

作者并不是单纯介绍几个已有模型，而是在交代一个技术背景：既有序列建模方法存在怎样的限制，Attention 又为什么值得被放到更核心的位置。

三、Encoder–Decoder：从序列到序列

补完前面的知识后，我重新回到 Encoder–Decoder 架构。

最初，我对它的理解相当粗糙：

Encoder 像是负责输入的 RNN，Decoder 像是负责输出的 RNN，二者通过上下文信息连接。

当然，这个理解并不完全准确。

Encoder 并不是去掉输出的 RNN，Decoder 也不是去掉输入的 RNN。更准确地说，Encoder 负责将输入序列转换为内部表示，Decoder 则利用这些表示生成目标序列。

以机器翻译为例：

输入：我喜欢人工智能

输出：I like artificial intelligence

Encoder 处理中文，Decoder 生成英文。

但为什么 Decoder 不仅需要 Encoder 的信息，还要知道自己之前输出了什么？

我最开始想到的是：输入与输出未必存在一一对应关系，甚至可能属于完全不同的语言。

后来才进一步意识到，问题不仅如此。

输出序列本身也存在依赖关系。

如果 Decoder 已经输出：

I like artificial

那么生成下一个词时，就必须考虑此前的英文上下文。

因此，在自回归生成过程中，Decoder 不仅需要理解原文，还需要根据已经生成的内容决定下一步输出。

至此，Encoder–Decoder 的基本工作逻辑终于清晰了一些。

不过，新的问题又来了。

Decoder 怎么知道生成某个词时，应该重点参考 Encoder 的哪个位置？

于是，Attention 登场了。

四、Attention：到底应该关注哪里？

传统的 Encoder–Decoder Attention 可以理解为一种动态的信息选择机制。

假设 Encoder 接收到四个 Token：

我 / 爱 / 水 / 课

并生成四个隐藏状态：

h1,h2,h3,h4h_1,h_2,h_3,h_4h1​,h2​,h3​,h4​

当 Decoder 准备生成第一个英文 Token I 时，它需要从这些隐藏状态中获取相关信息。

但不同位置提供的信息显然并不一样。

模型如何决定每个位置的重要程度？

答案是：计算匹配分数，然后使用 Softmax 得到注意力权重。

1. 点积：计算匹配程度

一种简单的评分方式是点积：

et,j=stThje_{t,j}=s_t^Th_jet,j​=stT​hj​

其中，sts_tst​ 表示 Decoder 当前用于查询的状态，hjh_jhj​ 是 Encoder 第 jjj 个位置的隐藏状态。

点积的结果是一个标量，可以作为两个向量的匹配分数。

当然，点积并不天然理解语义。真正让这种匹配具有任务意义的，是模型在训练中学习到的表示和参数。

2. Softmax：把分数转换成权重

假设四个位置的匹配分数是：

[1.792,0,0.693,0][1.792,0,0.693,0][1.792,0,0.693,0]

接下来使用 Softmax：

αt,j=exp⁡(et,j)∑kexp⁡(et,k)\alpha_{t,j}= \frac{\exp(e_{t,j})} {\sum_k\exp(e_{t,k})}αt,j​=∑k​exp(et,k​)exp(et,j​)​

计算之后，可以近似得到：

[0.6,0.1,0.2,0.1][0.6,0.1,0.2,0.1][0.6,0.1,0.2,0.1]

也就是说，Decoder 当前对第一个位置分配了约 60% 的注意力权重。

Softmax 最让我感兴趣的一点是，它并不是直接根据单个分数确定权重，而是根据所有分数之间的相对差异进行归一化。

如果只把第一个位置的分数从 1.792 提高到 10，它的注意力权重就会接近 100%。

但如果给所有分数同时加上相同的常数，Softmax 的输出却不会发生变化。

原来，注意力权重关注的是相对关系，而不是某个分数的绝对大小。

3. 加权求和：得到上下文向量

得到注意力权重后，便可以计算上下文向量：

Ct=∑jαt,jhjC_t=\sum_j\alpha_{t,j}h_jCt​=j∑​αt,j​hj​

代入刚才的例子：

Ct=0.6h1+0.1h2+0.2h3+0.1h4C_t=0.6h_1+0.1h_2+0.2h_3+0.1h_4Ct​=0.6h1​+0.1h2​+0.2h3​+0.1h4​

需要注意的是，CtC_tCt​ 仍然是一组数字构成的向量，而不是直接输出的英文单词。

Decoder 利用这个向量和自身状态，进一步计算输出词表上的概率分布，最终预测出一个 Token。

当 Decoder 进入下一步时，由于当前状态发生变化，注意力权重也可能重新分配。

Attention 并不是给每个 Token 永久指定一个重要程度，而是根据当前的信息需求，动态决定应该关注哪些位置。

这一点终于让我理解了，为什么上下文向量会随着 Decoder 的生成步骤不断变化。

五、从 Attention 到 Self-Attention：Q、K、V 是什么？

理解传统 Attention 后，再看 Transformer 中的 Self-Attention，就没有最开始那么陌生了。

不过，看到 Query、Key、Value 三个概念时，我还是疑惑了很久。

为什么同一个 Token 要产生三个不同的向量？

后来，我尝试把它们理解为：

  • Query（Q）：我现在需要什么信息？（我是谁？）
  • Key（K）：我这里有哪些特征，与你需要的信息有多匹配？（Yes or No）
  • Value（V）：如果你关注我，我能够提供什么信息？

Key 有点像检索目录，Value 则更像实际保存的内容。

当然，Key 并不是简单回答 Yes 或 No，而是与 Query 一起参与计算连续的匹配分数。

在 Self-Attention 中，每个 Token 都会根据输入表示，经过不同的可学习线性投影，生成自己的 Q、K、V。

Q=XWQQ=XW_QQ=XWQ​

K=XWKK=XW_KK=XWK​

V=XWVV=XW_VV=XWV​

其中，WQ,WK,WVW_Q,W_K,W_VWQ​,WK​,WV​ 是训练得到的模型参数。

接下来便是论文中的经典公式：

Attention⁡(Q,K,V)=softmax⁡(QKTdk)V\operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left(\frac{QK^T}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QKT​)V

第一次看到这行公式时，我只觉得一堆字母和矩阵挤在一起。

现在回过头来看，它其实可以拆成几个步骤：

首先，用 Q 和 K 的点积计算匹配分数。

然后，除以 dk\sqrt{d_k}dk​​ 进行缩放，避免维度较大时分数尺度过大，使 Softmax 过于饱和。

接着，通过 Softmax 得到注意力权重。

最后，利用这些权重对 V 进行加权求和，形成新的表示。

概括起来就是：

Q 提出查询，K 参与匹配，V 提供信息。

原来一整行看似复杂的数学公式，本质上描述的就是这样一个过程。

六、Multi-Head Attention：从全科医生到专科医生

继续往下阅读时，我又被模型的维度弄糊涂了。

原始 Transformer Base 使用 512 维的模型表示，但在多头注意力中，每个注意力头的 Q、K、V 维度却只有 64。

为什么维度反而变小了？

后来发现，原始 Transformer Base 使用了 8 个注意力头：

512=8×64512=8\times64512=8×64

对于每一个头，模型都会将完整的 512 维输入，通过独立的权重矩阵投影到 64 维空间。

这里假设输入有四个 Token。

八个注意力头各自完成计算后，再将输出拼接，并通过一个输出投影矩阵进行整合，得到 512 维表示。

理解这一点后，我突然想到一个很符合医工专业的比喻：

单头注意力像是一位全科医生，多头注意力则像是由多位专科医生共同参与的会诊。

每位医生都能查看患者完整的检查资料，但可能从不同角度提取自己关心的信息。

最后，再将不同角度的观察结果整合起来。

当然，这只是帮助理解的类比。实际模型中，各个注意力头的分工并不是人为规定的，它们可能学到不同的关系，也可能存在一定程度的冗余。

但至少，这个比喻终于帮助我理解了为什么模型要设计多个注意力头。

七、512 维：一个无法直观想象的世界

还有一件令我感到惊讶的事，就是 Transformer 的高维表示。

我们生活在三维空间中，四维空间已经很难直观想象，而原始 Transformer Base 中的 Token 表示却有 512 个维度。

这意味着，每个 Token 在模型内部都可以由一个包含 512 个数字的向量表示。

不过，这并不意味着第一个维度表示颜色，第二个维度表示形状，第三个维度表示语义。

神经网络的特征通常以分布式的方式存在，单独某一个维度未必能够对应人类容易理解的概念。

更有意思的是，同一个 Token 在不同上下文中，可以产生不同的隐藏表示。

例如，「水」出现在：

苹果、西瓜、哈密瓜、水果

与出现在：

大学生、期末、作业、水课

这两种语境下，模型可能提取出截然不同的上下文信息。

需要说明的是，这不代表「水」的初始 Token Embedding 必然发生了改变，而是它在经过注意力层及后续网络处理之后，形成了上下文相关的表示。

至于表示是否真的在向量空间中向「果」或「课」靠近，则需要进一步测量，不能仅凭直觉判断。

这让我第一次对表示学习（Representation Learning）产生了比较具体的认识。

所谓模型理解上下文，并不是像人一样在脑海里查阅字典，而是通过大量数值运算，在高维空间中不断构造与更新信息表示。

八、Attention Is All You Need，但也许不是 All We Need

读到这里，我开始思考一个与自己未来学习方向有关的问题。

我目前更感兴趣的是生物信息学、医疗器械建模，以及生物系统与人工智能之间的联系。

无论是 ECG、PPG 等生理信号，还是基因、蛋白质序列，都具有复杂的依赖关系。

Attention 提供了一种学习序列内部关联的方法，Transformer 也已经在多个生物医学任务中得到应用。

但真实生物系统并不只是由静态的关联关系组成。

神经系统还具有动态状态、反馈连接、突触可塑性以及不同时间尺度的记忆机制。

这不禁让我想到：

能不能构建一种更接近生物神经系统的新型网络架构？

能不能让模型在学习新知识时，不必总是依赖大规模的参数更新？

能不能将突触可塑性与现有神经网络架构结合起来，改善连续学习或者动态记忆能力？

当然，这些问题并不新鲜，相关领域已经有大量研究，也不能简单认为越接近生物结构的模型就一定越优秀。

但至少，它们为未来的学习提供了一些方向。

要真正研究这些问题，显然还需要补齐数学、神经网络、计算生物学以及实验方法方面的大量知识。

目前的我，甚至还在努力理解 Transformer 的基本架构。

不过，科研总得从最初的疑问开始。

九、写在最后

第一次阅读 Attention Is All You Need，最大的收获可能并不是终于学会了 Transformer。

事实上，我距离真正理解这篇论文还有相当长的一段路。

它的训练方法、模型优化、实验设计，以及许多架构细节，我都还需要继续学习。

但这次阅读让我明白了一件事：

一篇看不懂的论文，未必意味着它完全超出了自己的能力范围，也可能是因为尚未建立理解它所需要的知识体系。

从 FNN、CNN、RNN，到 Encoder–Decoder，再到 Attention、QKV 和 Multi-Head Attention，我逐渐发现这些概念并不是彼此孤立的。

一项新技术的提出，往往是建立在前人长期积累的工作之上，并试图解决既有方法留下的问题。

今后阅读论文时，我想自己应该多问几个问题：

作者究竟想解决什么问题？

为什么此前的方法不够好？

为什么作者选择这种设计？

它又有哪些尚未解决的局限？

或许，比起单纯记住一个公式，更重要的是理解公式背后的问题与思想。

2017 年，论文的作者们写下了：

Attention Is All You Need.

而作为一个刚刚接触深度学习不久的学生，我大概还得补上一句：

Attention Isn’t All I Need.

我还需要数学、代码、实验，以及很多很多耐心。

当然，也需要睡眠。

Sleep Is All My Need. 🥰
